GitHub App setup: __APP_PROFILE__

Create or repair a least-privilege GitHub App, configure organization Actions settings, and verify its installation.

1Check local prerequisites

This helper uses the locally authenticated gh CLI. It never writes the private key to disk or logs it.

Existing purpose-scoped App

Review App permissions Manage repository access
Rotate or repair the organization credential

This is only needed if the stored credential was revoked or expired. GitHub never exposes an existing private key again, so generate a new one in App settings first.

The selected PEM is sent only to this loopback service and is never stored on disk by the helper.

2Create a new or replacement App

Use this only when no App is configured or replacement is intentional. GitHub will show a confirmation page with this profile's minimum permissions. Webhooks and OAuth are disabled.

Maximum 34 characters.

3Install and verify

The organization variable __APP_VARIABLE__ and secret __APP_SECRET__ are now configured with all-repository visibility.

GitHub requires an organization owner to approve installation. Install the App, then return here. Repository-capable profiles must cover all repositories because they replace organization-wide credentials.

Security boundary
  • The service listens only on 127.0.0.1 and uses a random session token.
  • The one-time manifest code is exchanged directly between this browser and GitHub.
  • The returned private key is sent only to this loopback service over the same local session, then piped to gh secret set.
  • Stop the local service with Ctrl+C after setup.
